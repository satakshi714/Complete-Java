1. Introduction to JavaScript

JavaScript is a high-level programming language mainly used to add logic and behavior to websites, but it is no longer limited to browsers. It now powers frontend applications, backend servers, mobile apps, desktop apps, games, tooling, and even some AI-related workflows. Historically, it was created by Brendan Eich in 1995 for Netscape. The early names were Mocha and LiveScript before it became JavaScript. The language was later standardized by ECMA, so the official standard is called ECMAScript.

2. Runtime Environments

JavaScript needs a runtime environment to execute. The language itself gives syntax and rules, but the environment provides extra objects and APIs. In the browser, JavaScript gets access to window, document, BOM APIs, timers, and DOM APIs. In non-browser environments like Node.js, JavaScript gets different global capabilities such as file system access, process information, and server-side modules.

3. Features, Advantages, and Limitations

Main Features

High-level
You do not manually manage low-level memory like in C.
Dynamic / loosely typed
Variable type is decided at runtime.
Interpreted / JIT optimized
Modern engines parse, compile, and optimize code internally.
Single-threaded main execution model
One call stack executes one thing at a time.
Garbage collected
Unused memory is cleaned automatically.
Object-based and prototype-based
Objects are central, inheritance uses prototypes.

Advantages

  • Huge ecosystem and community
  • Runs almost everywhere
  • Fast development cycle
  • Great browser support
  • Frontend and backend with one language

Limitations / Challenges

  • Loose typing can create bugs if you are careless
  • Type coercion can be confusing
  • Security issues like XSS exist if you misuse browser APIs
  • Single-threaded behavior means heavy synchronous work can block the UI

4. Tokens and Syntax Basics

A token is the smallest meaningful unit of a program. JavaScript code is made from identifiers, keywords, literals, operators, separators, and comments. Understanding these is important because every statement is built from them.
Identifiers
Names given by programmer, like userName, total, calcSum.
Keywords

Literals

(), {}, [], ,, ;, :.

Identifier Rules

5. Variables

Variables are containers used to store data so it can be reused later. JavaScript has three main declaration keywords: var, let, and const. They are not identical, and choosing the correct one matters for scope, re-declaration, and safety.
KeywordScopeRedeclareReassignBest use
varFunction scopeYesYesOld code, avoid in modern code unless needed
letBlock scopeNoYesNormal changing variable
constBlock scopeNoNoValue reference should not be reassigned

Common variable operations

  • Declaration: let age;
  • Initialization: age = 20;
  • Declaration + initialization: let age = 20;
  • Reassignment: age = 25;
  • Redeclaration: allowed with var, not with let/const

6. Data Types

Data types tell JavaScript what kind of value it is handling. JavaScript divides values into two broad families: primitive and non-primitive. Primitive values are immutable and stored by value. Non-primitive values like objects and arrays are mutable and usually handled by reference.

Primitive Types

Number
Integers and decimals, for example 10, 3.14, NaN, Infinity.
String
Text inside quotes or backticks.
Boolean
true or false.
Undefined
Default value of an uninitialized variable.
Null
Intentional absence of value.
BigInt
Large integers beyond normal safe number range, e.g. 123n.
Symbol
Unique identifiers usually used in advanced object work.

Non-Primitive Types

  • Object
  • Array
  • Function
  • Date, Map, Set, RegExp, and other built-in object types

7. Type Conversion and Type Coercion

JavaScript can change data types in two ways. If the programmer changes the type manually, that is explicit type conversion. If JavaScript changes a type automatically to make an operation work, that is implicit conversion, also called type coercion. This is one of the most tested and most misunderstood parts of the language.

10. Control Flow

Control flow decides which part of the program executes and in what order. JavaScript supports conditional branching using if, else if, else, and switch. These statements let a program make decisions based on conditions. 
if (score >= 90) {
  console.log("Excellent");
} else if (score >= 60) {
  console.log("Pass");
} else {
  console.log("Try again");
}

11. Loops

Loops are used when the same logic must run repeatedly. The most important question is not just what loops are, but when each one should be used. Use for when the count is known, while when repetition depends on a condition, do...while when code must run at least once, for...of for values, and for...in for keys or indexes.

13. Scope, Hoisting, TDZ, and Closures

Scope defines where a variable can be accessed. JavaScript mainly uses global scope, function scope, and block scope. Hoisting is JavaScript's internal behavior of registering declarations before execution. The temporal dead zone applies to let and const: the variable exists, but cannot be accessed before its declaration line. Closures happen when an inner function remembers and uses variables from an outer function even after the outer function has finished.

Types of scope

  • Global scope: accessible almost everywhere
  • Function scope: accessible only inside a function
  • Block scope: accessible only inside { } block
console.log(a); // undefined
var a = 10;

// console.log(b); // ReferenceError

14. Call Stack and Debugger

The call stack is the structure where JavaScript keeps track of function calls. It follows LIFO order: the last function entered is the first one completed. During execution, JavaScript creates execution contexts. The global execution context is created first, and whenever a function is called, a new function execution context is pushed onto the stack. The debugger keyword pauses execution so you can inspect variables, control flow, and the stack in browser developer tools. 
function one() {
  two();
}
function two() {
  debugger;
  console.log("Inside two");
}
one();

15. Strings, Properties, Methods, and Interpolation

Strings represent text data. JavaScript supports single quotes, double quotes, and template literals using backticks. Template literals allow string interpolation, meaning variables or expressions can be inserted inside a string using ${...}. Strings are primitive values, but JavaScript temporarily wraps them with a string object so you can use methods on them.

Useful string members

  • Property: length
  • Methods: toUpperCase(), toLowerCase(), split(), replace(), indexOf(), includes(), slice(), substring(), trim(), charAt(), charCodeAt(), at()

19. Synchronous vs Asynchronous JavaScript

Synchronous JavaScript runs line by line, one task at a time. Asynchronous JavaScript allows long-running tasks like timers, network calls, and some browser APIs to run without blocking the main thread. JavaScript still uses a single call stack, but the environment plus task queues make async behavior possible.

20. Timers

  • setTimeout() runs a callback once after a delay
  • setInterval() runs a callback repeatedly after each delay interval
  • clearTimeout() cancels timeout
  • clearInterval() stops interval

21. Promises

A promise represents the eventual completion or failure of an asynchronous operation. A promise has states: pending, fulfilled, and rejected. Promise handlers such as .then(), .catch(), and .finally() let you react to the result in a controlled way. 
const p = new Promise((resolve, reject) => {
  const ok = true;
  if (ok) resolve("Done");
  else reject("Failed");
});

p.then(value => console.log(value))
 .catch(err => console.log(err))
 .finally(() => console.log("Always runs"));

22. Fetch and API Flow

The fetch() function sends an HTTP request and returns a promise that resolves to a Response object. That response is not immediately the final usable data. It must often be converted using methods such as .json(), .text(), .blob(), or .formData(). The conversion method itself is asynchronous, so it returns another promise. 
fetch("https://dummyjson.com/products")
  .then(response => response.json())
  .then(data => console.log(data.products))
  .catch(error => console.log(error));

23. Async and Await

An async function always returns a promise. The await keyword can only be used inside an async function or supported module context, and it pauses that async function until the promise settles. This makes asynchronous code look more sequential and readable. 
async function loadProducts() {
  try {
    const response = await fetch("https://dummyjson.com/products");
    const data = await response.json();
    console.log(data.products);
  } catch (error) {
    console.log(error);
  } finally {
    console.log("Cleanup");
  }
}

25. DOM (Document Object Model)

The DOM is a tree representation of the HTML document. Every HTML tag becomes a node object. JavaScript can read, create, modify, remove, and style these nodes at runtime. This is what makes interactive webpages possible.

Core DOM tasks

  • Select elements
  • Read and change content
  • Read and change attributes
  • Read and change styles
  • Create and append new elements
  • Remove elements
  • Attach event listeners
const heading = document.getElementById("title");
heading.textContent = "Updated";
heading.style.color = "tomato";

26. Events

Events are signals fired by the browser when something happens, such as a click, input, submit, change, key press, page load, or mouse movement. JavaScript responds to these by attaching event listeners. Event-driven programming is the heart of interactive web applications.

Common event types

  • click
  • input
  • change
  • submit
  • keydown
  • mouseover
  • load
const btn = document.getElementById("btn");
btn.addEventListener("click", () => {
  console.log("Button clicked");
});

27. Final Revision Strategy

Study JavaScript in layers. First understand values, variables, and operators. Then move to control flow and loops because they build logic. After that, functions, scope, hoisting, and closures form the core mental model. Once the synchronous model is clear, move into asynchronous JavaScript, promises, fetch, and async/await. Finally, browser-side JavaScript becomes powerful when BOM, DOM, and events are added. That order matters because each later topic depends on earlier understanding.
